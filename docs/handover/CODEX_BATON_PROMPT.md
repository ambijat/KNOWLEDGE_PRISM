## Project location

Repository root after cloning.

## Non-negotiable rules

1. Do not delete inherited artifacts.
2. Do not treat folder names as final ontology.
3. Do not claim full-text reading unless evidence grade confirms it.
4. Do not pull external papers yet.
5. Maintain reproducibility: every processed file must be generated by a visible script.
6. Preserve UK English in documentation.
7. All generated outputs must go into `outputs/`, `data/processed/`, or `data/verification/`.

## Immediate Codex tasks

### Task 1: Validate the project

Run:

```bash
python3 scripts/00_validate_project.py
python3 scripts/03_report_status.py
```

Fix path or dependency problems only if they prevent these scripts from running.

### Task 2: Harden master-register regeneration

Improve `scripts/01_build_master_register.py` so that it can regenerate:

```text
data/processed/MASTER_CORPUS_REGISTER_PRELIMINARY.csv
```

from:

```text
data/raw/solemon/solemon_crawl.csv
data/raw/recoll/recoll_corpus_manifest.csv
```

### Task 3: Improve duplicate classification

Add dedupe fields:

- normalised title
- normalised filename
- file size bucket
- probable edition marker
- duplicate reason

### Task 4: Create core-corpus candidate export

Generate:

```text
data/processed/CORE_CORPUS_CANDIDATES.csv
```

Do not overfit. Use transparent keyword rules and mark them as provisional.

### Task 5: Verification interface

Create a script that takes the first 50 rows from:

```text
data/verification/BRIDGE_CONCEPTS_VERIFICATION_QUEUE.csv
```

and produces a review checklist:

```text
outputs/reports/BRIDGE_VERIFICATION_SAMPLE_50.md
```

The checklist should ask whether the thesis/concepts are supported by title, front matter, chapter sample, or full text.

## Desired maturity level before major software development

The project is mature enough for larger Codex work only when:

- project validation passes,
- master register regenerates reproducibly,
- duplicate logic is documented,
- at least 50 bridge concepts are verification-ready,
- domain-boundary document is stable.
